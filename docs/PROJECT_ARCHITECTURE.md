# Money Back 项目架构

## 结论

Money Back 先固定为“研究内核 + 每日信号 + 薄网页”，不先建设完整交易网站。

策略逻辑只能存在于 Python 研究内核。未来网页读取内核生成的结果，不复制排名、过滤、止损或仓位计算。这样网页改版或故障不会改变策略，也不会影响每日信号。

## 三层结构

### 1. 研究内核

负责数据、信号、回测、成本、风险规则、参数配置、测试和版本比较，是唯一权威逻辑。

- `src/`：可复用研究与回测代码。
- `configs/`：不可含糊的策略版本定义。
- `notebooks/`：研究过程与已执行结论。
- `outputs/`：小型结果表和图表。
- `tests/`：回归测试、无前视检查和关键边界条件。

### 2. 每日信号

收盘后由研究内核生成一个结构化信号文件，至少包含：

- 数据日期与策略版本；
- 六只或动态 ETF 池的动量排名；
- 四指数市场门状态；
- 当前持仓、明日目标持仓与替换原因；
- 风险状态、建议动作与数据完整性检查；
- 信号生成时间和输入数据摘要。

先使用手动执行与纸面跟踪，不直接接券商下单。

### 3. 薄网页

个人阶段优先使用 Streamlit。页面只负责展示：

- 今日信号与执行清单；
- 当前持仓、排名和市场门；
- 历史权益、回撤和基准对比；
- 当前策略版本与最近一次研究结论；
- 纸面信号与实际成交偏差。

只有出现多用户、权限、常驻任务、移动端体验或券商接口需求时，才升级为 FastAPI + 独立前端。

## 版本路线

| 版本 | 目标 | 完成门槛 |
|---|---|---|
| V0.1 | T5 逆向还原与严格基线 | 已执行笔记、配置和基线指标固定 |
| V0.2 | 研究可信度 | 动态 ETF 池、walk-forward、滚动三年、可执行风险降档 |
| V0.3 | 每日可用 | 自动生成信号文件，连续纸面跟踪 4–8 周 |
| V0.4 | 使用体验 | Streamlit 只读页面，不复制策略逻辑 |
| V1.0 | 实盘候选 | 数据源、执行偏差、回归测试和风险门槛全部通过 |

## GitHub 固定方式

使用私有仓库。代码、配置、文档、测试、已执行笔记和小型结果进入版本控制；行情缓存、虚拟环境、密钥、账户信息和券商凭证不进入仓库。

建议里程碑标签：

- `v0.1-t5-reconstruction`
- `v0.2-dynamic-universe`
- `v0.3-daily-signal`

每个版本都必须保留配置、数据截止日、执行假设、核心指标和已知局限。新研究创建新版本，不覆盖旧基线。
